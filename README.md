# 分块校验树与差异定位（从 0 实现）

仓库里只有这份说明、`samples/**` 和 `.gitignore`，没有任何实现代码。

## 1 范围

交付物（仓库根）：`checktree/` 包（Python 3.13 标准库，入口 `python -m checktree`）、`web/diff.html`
（自包含页面）、`tests/`（`unittest`，只读 `samples/`）。

```text
python -m checktree build --blocks <清单> --tree <树文件> [--branch <k>]
python -m checktree check --tree <树文件> --blocks <新清单> --changes <变更集> [--out <新树>] [--page <页面>]
```

不做：不读不写块内容（摘要由清单给出）；不做分布式、并发、压缩、加密与传输；只用标准库，不联网。

## 2 口径与公式

- **块与摘要**：块固定 4096 字节，块号从 0 起连续，块 i 覆盖 `[i*4096, min((i+1)*4096, 总长))`
  （0 块是空清单）。摘要 = 块内容的 SHA-256，样例只给摘要。
- **分支因子 k**：2 ≤ k ≤ 64，`build` 用 `--branch` 指定（缺省 4），树内恒定，`check` 以树头为准。
- **哈希**：叶 `H(0,i) = sha256(0x00 ‖ u64be(i) ‖ 摘要字节)`，父
  `H(d,j) = sha256(0x01 ‖ u64be(子数) ‖ 子哈希按序号拼接)`；`u64be` 是 8 字节大端无符号整数，末组
  不足 k 个按实际子数算，不补空节点。
- **分层**：第 0 层是叶（块号升序）；每层从左到右每 k 个一组合成上一层一个节点，>1 个就继续往上，
  只剩 1 个是根。单块树根 = 叶哈希，空清单根 = `sha256(b"")`。
- **坐标与路径**：坐标写作 `层:序号`（层号 0..d）；路径是根到叶的每个子下标、从根那头写起、`/` 分隔
  （如 `1/3`），只有根时写 `-`；第 d 层节点 j 是第 d+1 层节点 `j//k` 的第 `j%k` 个子节点。
- **冻结块**：树头 `frozen` 列的块，叶值取自树文件（上一轮留下的旧值），必须原样保留、不许重算，
  它们的祖先照常重算；变化块落在冻结块上判不通过。

## 3 数据结构与增量更新

树是分层表 `层 → 序号 → 32 字节哈希`，节点记录定长（见 4.3）；核对只动路径上的 `层数` 个记录。

一轮 `check`：① 读树头与变更集；② 逐条核对（见 4.4）；③ 按新摘要算变化块的新叶，自下而上重算第
1..d 层祖先，共用祖先只算一次；④ 给 `--out` 才写回树，再写页面。**允许重算的范围**：只有变化块的叶
（被删除的块没有叶）和它们在变更后仍存在的祖先，按坐标去重；没涉及的记录一个字节都不许改。整树
重算即使哈希自洽，也过不了第 5 节第 3、4 条。

## 4 输入输出与文件格式

本节文件一律 UTF-8 无 BOM、行尾单 `\n`、末行有换行；数字十进制零填充，哈希小写十六进制。

### 4.1 分块清单 `<名>.v1.tsv`、`<名>.v2.tsv`

定长 93 字节一条：`块号(8) \t 偏移(12) \t 长度(5) \t 摘要(64) \n`；块号升序连续从 0 起，偏移 =
块号 × 4096。第 i 块就在 `i × 93` 处，不必读完整个清单。

### 4.2 变更集 `<名>.changes.tsv`

一行一条、制表符分隔、按块号升序：`块号 \t 动作 \t 旧摘要 \t 新摘要`；动作只有 `替换`、`新增`
（旧摘要写 `-`）、`删除`（新摘要写 `-`）。新增与删除只能在末尾：新增块号正好是 `旧块数 … 新块数-1`，
删除的正好是 `新块数 … 旧块数-1`，同一轮不许既有新增又有删除，空文件表示没有变化。变更集是「这一轮
动哪些块」的唯一入口。

### 4.3 树文件 `<名>.tree`

头 5 行依次是 `format 1`、`branch <k>`、`blocks <块数>`、`frozen <块号|->`、`nodes`，第 6 行起是节点
区。每条记录定长 77 字节：`层(2) : 序号(8) 空格 哈希(64) \n`，层升序、层内序号升序；第 (d,i) 个节点
的记录在节点区第 `77 × (前 d 层节点数 + i)` 个字节处。`frozen` 列冻结块号（升序、空格分隔，没有写
`-`）；`build` 的树没有冻结。

### 4.4 stdout

`build` 三行：`块数 <n>`、`层数 <n>`、`根 <hex>`。

`check` 通过时每行依次是 `核对 通过`、`块数 <n>`、`变化块 <块号 …|->`、`重算节点 <层:序号 …|->`、
`重算数 <n>`、`根 <hex>`，再按块号升序每个变化块一行 `路径 <块号> <子下标序列>`；`变化块` 含被删除
的块，`路径` 不给被删除的块写，`重算节点` 按层升序、层内序号升序。

不通过时 stdout 只有一行，原因只有 `清单块数与变更集不符`（不带块号）、`块 <号> 位置非法`、
`块 <号> 已冻结`、`块 <号> 旧摘要与树不符`、`块 <号> 清单与变更集不符`（取最小的不合规块号）。
退出码 0 = 通过或建好、2 = 核对不通过、其余 = 输入不可用；后两种不写文件，原树不动。

### 4.5 页面 `web/diff.html`

`check --page <路径>` 用这一轮结果写一份自包含页面（UTF-8、单文件、双击可开、不引外部资源、不联网），
交付时仓库里要有一份用样例生成的：

1. `id="summary"` 的 `<dl>`：`块数`、`变化块`、`重算数`、`根` 四项的值与 stdout 对应行逐字相同；
2. `id="tree"` 的 `<svg viewBox="…">` 画出这一轮的路径，每个路径节点是
   `<g class="node" data-node="层:序号">`，集合 = `重算节点`；变化块的叶 class 为 `node changed-block`
   （红）、其余为 `node changed`（高亮）；相邻节点间有一条 `<line data-edge="父/子">`；被删除的块没有
   叶，只在祖先路径里；
3. 路径、块号、计数都取自引擎结果，页面不重算哈希。

## 5 性能与验收口径

规模：单树 ≤ 400 万块（k=4 时层数 12）。一轮 `check`（变化 ≤ 1 万块，含读树、写树、写页面）≤ 5 秒；
峰值内存与块数无关——400 万块与 40 万块两次核对的峰值之差 ≤ 32 MiB（`tracemalloc` 扣基线）；
`build` 允许全量重算。

1. 环境：Python 3.13、只用标准库、无构建无网络；仓库根目录直接跑；`python -m unittest` 只读
   `samples/` 且能跑通。
2. 逐行比对：`samples/expected/<名>.check.txt` 前几行是应当得到的 stdout，末行 `退出码 <n>` 只对
   退出码；`--out` 写出的树与 `samples/expected/<名>.tree` 逐字节相同。
3. 只重算变化路径：`重算节点` 必须精确等于第 3 节的集合；带冻结的样例里只有变化路径上的记录会变，
   别的记录连字节都不许动。
4. 确定性：同一输入跑两遍，stdout、输出树、页面逐字节相同；页面双击能开、4.5 三项齐全。

## 6 样例说明

`blocklists/<名>.v1.tsv`、`.v2.tsv`、`.changes.tsv` 与 `trees/<名>.tree` 同名成套；`expected/<名>.check.txt`
是应当逐行得到的 stdout 与退出码，`expected/<名>.tree` 是 `--out` 应当写出的树。不带冻结的样例里，
`trees/<名>.tree` 就是 `build` 那份 v1 清单应当写出的树。样例是小尺寸切片，规模用例不入库。

| 样例 | 覆盖 |
| --- | --- |
| single-replace | k=4，12 块替换第 7 块：重算 3 个节点，路径 `1/3` |
| multi-frozen | k=4，17 块替换 3/5/9/12，带两个冻结块：共用祖先只算一次，冻结值不动 |
| append-tail | k=2，5 块变 6 块、末尾新增：叶与右侧父节点一起重算 |
| truncate-tail | k=4，12 块变 11 块，末尾删除第 11 块并替换第 3 块：删除块只贡献祖先 |
| no-change | k=4，7 块、空变更集：变化块与重算节点是 `-`，树一个字节不变 |
| stale-record / apply-to-frozen | k=4，核对不通过：旧摘要与树不符、变化块落在冻结块上；不写文件 |

`samples/notes.md` 是现场记录：几百万块每轮核对都重算整棵树，要几个小时。
